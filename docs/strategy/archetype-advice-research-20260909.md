# 角色体系与评分缺口调查（0.111.0）

本轮为数据与源码调查，不修改生产评分、不启动游戏。基于本机安装的 `data_sts2_windows_x86_64/sts2.dll`，用已有 ilspycmd 定向提取 5 个角色卡池及 16 个卡牌／Power 实现；本地材料保留在 `.local/archetype-research/`，不提交反编译源码。卡池生成条目数为 Ironclad 90、Silent 91、Regent 91、Necrobinder 91、Defect 91，共 454；这是角色卡池条目数量，不是本轮逐牌审查数量，也不包括所有中立／生成／Mod 牌。

## 结论

可以从数据建立比当前标签计数可靠得多的体系判断，但应识别资源来源、转换、收益与代价，而不是给整副牌强行贴一个流派。当前模拟层已经理解许多角色机制，奖励／商店评分没有使用这些语义；“模拟支持”不等于“选牌评分正确”。

## 五角色的可分析结构

| 角色 | 体系轴 | 必须区分的角色 | 评估条件与失败点 |
|---|---|---|---|
| Ironclad | 消耗转抽牌／防御、力量与多段攻击、防御转伤害、血量换启动 | 消耗手段、可消耗燃料、触发收益的 Power、终结输出 | 不只数 Exhaust：检查技能燃料是否耗尽、抽牌是否被禁、启动成本与防御能否覆盖 |
| Silent | 弃牌／Sly、Shiv、多段触发、Poison | 主动弃牌入口、被弃后获利组件、抽牌与能量供给、输出 | 有 Reflex／Tactician 不代表能稳定循环；没有廉价弃牌入口时，组件可能成为负担 |
| Regent | Stars 供给与消耗、Forge／SovereignBlade、生成牌转换 | 产星、耗星、锻造、剑的费用与重复攻击、过牌 | 星星与能量不能合并；有耗星终结牌但没有产星会卡，锻造数值也不能直接当永久成长 |
| Necrobinder | Osty、Doom、Soul 及其触发收益 | 召唤／维持 Osty、利用其 HP 的输出、叠 Doom、Soul 生成与收益组件 | Doom 关注斩杀阈值及敌方行动时序；Soul 是会消耗的生成抽牌资源，Osty HP 同时影响攻防 |
| Defect | 充能球／Focus、冰球防御、激发与循环、Claw 等重复成长 | 产球、球槽、Focus、激发、循环与防御 | “Orb 标签多”不保证球序正确；额外产球可能激发已有球。Claw 增长属于本战，不是永久培养 |

表中体系轴是机制推断，不是胜率排行。尚未逐一核对所有轴的卡牌、遗物与敌人交互，不能宣称全面覆盖。

## 定向核对到的实例

| 当前原生实现 | 确认事实 | 对评分的含义 |
|---|---|---|
| `Reflex`、`Tactician` | 都是基础 3 费 Skill、带 Sly；前者打出抽 2，升级抽 3；后者获 1 能量，升级获 2 | 不沿用一代的不可打出模型，也不把它们当无条件廉价资源；需联动弃牌／Sly 入口 |
| `BattleTrance` | 0 费，先抽 3，再施加 NoDraw | 当前仅凭 Draw 标签加分会漏掉阻断后续抽牌的代价 |
| `Soul` | 0 费 Token，Exhaust，抽 2，升级抽 3 | 应识别 Soul 生成牌带来的间接抽牌，而不是把所有 Cards 变量当抽牌 |
| `Glow` | 1 能量，产 1 星，当前抽 1，并提供下回合抽牌；升级增加星星 | 当前评分只覆盖部分抽牌，漏掉产星与延迟抽牌的结构价值 |
| `Unleash` | 伤害动态计算引用存活 Osty 的当前 HP | 仅读取静态 Damage.BaseValue 无法可靠代表当前牌组中的输出能力 |
| `DoomPower` | 检查当前 HP 不高于 Doom 数量，在对应结算时机处理死亡 | Doom 不能简单作为每点固定即时伤害计分；缺口大小与结算时序重要 |
| `DarkEmbracePower`、`FeelNoPainPower` | 消耗触发抽牌／格挡；Dark Embrace 还区分 Ethereal 的延后抽牌 | 入口和收益必须分开；自动消耗时机不同，不宜统一按一次立即抽牌 |
| `CorruptionPower` | 对技能费用及技能消耗行为施加修改 | 与消耗收益存在联系，但会消耗技能储备；不意味着已经形成无限 |
| `SovereignBlade` | Retain，内部保存伤害和攻击次数；Forge 相关行为改变战斗中的牌状态 | 不能仅看基础伤害或将锻造误计成永久跨战成长 |
| `Glacier`、`Defragment` | 前者提供格挡并生成冰球，后者施加 Focus | 即时格挡、未来球收益、球槽和激发要分开计量 |
| `Claw` | 打出后增强本战 AllCards 中的 Claw | 同名牌的价值不是统一递减；但持续增加同名牌也受抽牌与启动限制 |
| `AccuracyPower`、`HauntPower` | 前者关联 Shiv 伤害；后者在打出 Soul 后对可命中敌人产生伤害 | 生成牌与触发收益有明确关系，需估可触发次数，而非只计相同标签数量 |

这些是定向提取所得机制摘述，不是完整效果重现。升级、词条、遗物和局内变化必须继续沿原生数据捕获。

## 现有评分的明确缺口

代码入口：`src/Advice/RunAdvice.cs` 与 `RunAdviceCapture.cs`。

1. `AdviceCard` 有 Energy Cost，没有 Stars Cost、Forge、Osty、Soul 生成、抽牌禁用等字段。新增角色核心资源尚未进入建议数据契约。
2. `AdviceTag.Exhaust` 同时承担自消耗、消耗入口、消耗收益，无法区分“燃料”与“引擎”。Discard 也存在同类混淆。
3. `CardValue` 只遍历固定 archetype 列表，发现第一个满足两张支持牌的标签就退出。因此双体系配合受枚举顺序影响，而非实际贡献。
4. `card.Type == Power` 一律归入 Scaling，无法区分持续成长、固定支持和负面时序。
5. 同名牌一律每张扣 3 分，没有识别 Claw、循环组件的协同，也没有估抽到启动组件的稳定性。
6. 基础牌移除只按非基础攻击／格挡牌数量等粗略条件判断；非基础移除复用“加一张牌”的 CardValue，缺少删牌前后比较。不能据此证明移除后能无限。
7. `Known` 对所有原版程序集卡牌为真。它目前表示原版来源，而非效果已被完整评分规则覆盖；需要把来源与规则覆盖程度分开。
8. `FallbackValue` 表示通用参考而非完成语义识别。给未覆盖机制显示精确一位小数，也不会自动增加可信度。

## 建议实现方式

保留现有纯值 Advice 层，新增显式的机制特征，原生模型只在主线程捕获。第一批只覆盖经核对的卡牌与效果，不写猜测性的通用反射解析器。

- 资源：能量／星星分别记录产生、消耗与发生时点。
- 过牌：当前抽牌、下回合抽牌、生成可抽牌 Token、弃牌入口、抽牌禁止分别记录。
- 消耗：自消耗、可选／强制消耗其他牌、消耗收益分别记录。
- 角色机制：Forge、Soul、Osty、Doom、充能球类型／Focus 设独立特征。
- 收益与代价：启动费用、一次性燃料、HP 代价、延迟收益、不适用条件、规则覆盖说明。

推荐分由“加入前后结构差”得出：补足短缺的入口或供给才获得较高边际分，只有收益组件但没有入口时降低协同；删除关键入口产生负分。原通用牌面评分可保留为基线，但机制分应可解释、有限，不能让标签数量无限累加。

不先设计笼统的“无限检测器”。有限短线模拟只给“观察到循环”；宣称可重复无限还需证明每次循环资源不减少、可重复牌未消耗、抽牌可持续、敌人／回合限制允许，不能把某段增长当通用证明。

## 最小验收矩阵与顺序

第一批建议 Silent 弃牌／Sly + Ironclad 消耗：原生入口及已有模拟支持更明确，可验证“引擎不可错删”。第二批补 Regent 的双资源／Forge 与 Necrobinder 的 Soul／Osty／Doom，避免新增角色继续按通用牌面估值。Defect 的球序与激发需要小场景验证，不仅靠标签。

至少验证：

- 同一收益组件，在没有入口／一个入口／入口已经充足的牌组里边际分不同。
- 原有关键组件被移除后，不能仍报告循环成立。
- Battle Trance 的 NoDraw 与后续抽牌相冲突时，评分不能只增加。
- 同数量标签但角色不同的牌组，不能靠标签堆叠产生相同的虚假协同。
- 星星供给不足与能量不足分别识别；Soul 生成不能等同普通抽牌牌。
- Claw 与 Forge 不计入永久成长。
- 固定原生小战斗比较候选前后的启动、防御、资源与完整状态；奖励／商店 UI 另验分数刷新及说明。

研究交付不代表这些规则已实现，也不承诺评分优于玩家或整局胜率提高。
