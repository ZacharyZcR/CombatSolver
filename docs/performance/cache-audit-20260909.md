# 搜索缓存审查（2026-09-09）

源码基线：`aa49edf`。本轮为静态调用链审查，没有启动游戏、采集新 trace 或修改行为。下面是候选方向与验证合同，不是已经实现或测得的加速。

## 当前缓存边界

| 缓存 | 所有者及键 | 已有复用／清理 |
|---|---|---|
| 卡牌指纹与选择键 | `PredictedCard.PreviewStorage`，由存储身份代表牌面版本 | 普通 Fork 共享存储；MutablePreview 首次写入克隆，独占写入失效；外部可变附属模型禁用 |
| 有序／无序／循环牌堆指纹 | `SimCardPile`，容器内隐式版本 | Fork 复制缓存值；增删和牌面写入整堆失效 |
| 威胁预测 | `SearchRunContext.ThreatProjectionCache`，完整状态键＋回合偏移 | solver／worker 局部；回收检查点清空 |
| 结束回合探测 | `StandPatCache`，状态键 | 缓存标量评估，释放临时模拟器；回收检查点清空 |
| 覆盖摘要 | `CoverageCache`，风险签名 | solver／worker 局部，和较大缓存一起清空 |
| Hook 监听器 | 模拟状态中的列表 | Fork 重映射；结构变化失效；未知第三方可变结构保守重建 |
| 完整路线磁盘缓存 | `SolvedRouteCache`，构建／Mod／原生状态／政策等身份 | 最多 64 项；只写首条，已有文件不更新；显式重算及测量不读 |
| 转置与循环账本 | 状态与策略标签 | 不全是可随意淘汰的缓存；循环配额账本属于搜索语义 |

主要代码：`src/Engine/Common/PredictedCard.cs`、`SimCardPile.cs`；`src/Search/CombatBeamSolver.Models.cs`、`StateEvaluation.cs`、`Retention.cs`；`src/Search/SimulatedCombatState.cs`、`.Fork.cs`；`src/Runtime/SolvedRouteCache.cs`、`SolverController.cs`。

## 优先级 1：预测洗牌缓存原型

`StateEvaluation` 每个 Snapshot 汇集 discard→draw→hand，再由 `BuildProjectedShuffleOrder` 克隆 RNG、排序和洗牌，遍历全部牌计算指纹／估值。即便组成牌堆及 RNG 没变，也会重复。这与已有单卡／牌堆指纹缓存不是同一层。

候选：每个 worker 内有界缓存，不做全局并发字典。先保留输入次序建立精确身份，再考虑是否能证明跨牌堆移动的规范化等价；不能直接把三个无序指纹相加。排序相等的不同实例、动态字段和 RNG 完整状态必须覆盖。不能仅使用 Shuffle.Counter。

还需处理一个隐含输出：调用者复用洗牌后的 liveCards 计算后续指标。缓存命中只返回 key/value、跳过列表变换，并不自动证明等价；要审查所有下游次序依赖，包括浮点累加。可以先缓存原输入索引的排列、命中后重排当前实例，避免持有父分支卡牌，但这又增加内存和搬运成本，必须测量。

最小验证：同根原版排序／RNG 消耗逐项比较；顺序相等牌、移牌、生成牌、附魔修改、相同 counter 不同 RNG 状态、父子兄弟隔离。再比较固定工作量多场景的命中率、键成本、总分配、完整动作与非时序指标。只有命中节省超过查表和重排成本才保留。

## 优先级 2：让缓存观测支撑容量决策

已有阶段指标不能回答 ThreatProjection／StandPat／Coverage 的命中率、条目峰值、检查点清空次数和清空后的重复计算量。`TransitionCacheHits = 0` 是固定输出，不能用它推断这些缓存没有命中。

先加 worker 私有标量计数，只在现有诊断开启时累计并在阶段结束汇总，不逐节点写日志。需要：lookups/hits/misses/peak entries/resets；测命中路径开销和未命中计算开销。跨 worker 重复率先离线分析样本键，不立刻引入锁和共享字典。

`ResetReclaimableCaches` 同时替换所有三个字典。是否值得保留小型 Coverage 缓存，是数据问题：必须证明占用有界、命中受益且没有保留大对象图，不能为了命中率破坏 GC 检查点的释放目标。

## 优先级 3：路线缓存更新策略

`StoreFirst` 遇到既有文件直接返回。显式重算会绕过读取，但重新找到更好的路线也不会更新同键文件。因此后续自动恢复仍可能使用第一条路线。这是明确的更新策略限制，不表示会复用不匹配的根。

候选：仅在同键、同目标、完整性和既有路线质量比较判定严格更优时原子替换；平局不抖动。不能只按更高 HP 或更高 score 更新，需兼顾药水、成长、目标约束、回合与不完整结果；用户采用的当前回合截断路线继续不写。需要跨进程重载、取消、旧文件保留、错误不吞掉和更差路线不覆盖的合同。

这项主要改善缓存结果质量，并非每次搜索的速度。

## 暂不优先

- 单卡估值缓存：历史实验总分配反而增加约 0.08%，收益尚不足；不把旧实验重复包装成新优化。
- 任意放宽 MutablePreview 失效：当前 setter 暴露可变引用，不能根据“看起来没改”保留缓存；需要明确写入口或版本合同。
- 全局共享威胁／状态缓存：现有键依赖 solver 固定根、政策与 forecast 上下文，跨根必须补齐身份；并发同步及引用保留可能抵消收益。
- 完整转移缓存：动作、原生选择、策略配额和状态重映射复杂，不能缓存带父分支引用的 simulator 后交给别的分支。
- 延长循环账本或转置表寿命不能按普通缓存容量方案处理，会影响搜索配额和结果。

## 建议顺序

先加最小观测，再做预测洗牌的 worker 内有界原型；路线缓存优胜替换单独作为质量修复。保留通过精确对照的候选后，才运行固定工作量性能实验。当前没有证据承诺整场加速比例，也未改变已安装游戏。
